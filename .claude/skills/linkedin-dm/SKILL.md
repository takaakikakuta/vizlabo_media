# LinkedIn の DM を作る

`/linkedin-dm <プロフィール（＋受信メッセージ）をそのまま貼る>`。作業ディレクトリは `vizlabo_media`。

送り手は角田崇明。事例マニア（vizlabo.com）の運営者として送る。相手の領域に近い「事例セレクション」をこのリポジトリから1本選び、「こんな感じでやっています」と紹介するだけの DM。返信を求める質問、商談・面談への誘い、事例製作代行の宣伝は入れない。

## 入力

$ARGUMENTS

区切りなしのコピペがそのまま貼られる前提で扱う。入力が空なら「プロフィール（と受信メッセージ）を貼ってください」とだけ返して終える。

## 手順0：自動判定

貼られたテキストを読み、どちらかに判定する。

- **パターン2（受信メッセージへの返信）**：送り手（角田）に宛てたメッセージ文が含まれている。手がかりは「角田様」「はじめまして」「つながりありがとうございます」「ご挨拶」「〜させていただいております」「ご興味があれば」「お打ち合わせ」など、相手から角田への呼びかけ・挨拶・案内文。
- **パターン1（承認後にこちらから送る）**：上記がなく、プロフィール情報（見出し・会社・職歴・概要・投稿など）だけ。

判定したら、テキストをプロフィール部分と受信メッセージ部分に分ける。どちらとも判断しにくいときはパターン1として進め、出力の冒頭にその旨を1行で書く。

## 手順1：相手の領域を特定する

- 相手（またはその会社）は、誰のどんな課題を解決しているか
- 業界・製品・サービスのキーワードを5〜10個出す。日本語の同義語も足す（例：OCR → 「AI-OCR|OCR|紙|請求書」）
- パターン2では、受信メッセージで相手が売り込んでいる内容を最優先の手がかりにする
- 相手の会社のドメインや製品名が分かれば控えておく（手順2の `--vendor` に使う）

## 手順2：事例セレクションを選ぶ

公開中の事例セレクション（`content/articles/sen-*.json` のうち hidden・draft でなく、publishedAt が今日以前のもの）を横断検索する。検索は次のスクリプトで行う。タイトル・リード・見出し・本文に加え、収録事例の提供元ドメイン・製品名・導入企業名・業種・タグ・課題文まで見る。

```bash
node scripts/linkedin/find-sen.mjs <キーワード...> [--vendor <ドメイン|会社名|製品名>] [--top 5]
```

- キーワードは正規表現。同義語は `"AI-OCR|OCR"` のように `|` でまとめる
- `--vendor` に相手の会社ドメイン・社名・製品名を渡すと、その提供元の事例が収録された記事を「提供元一致」として最優先で出す
- 当たりが薄いときはキーワードを変えて2〜3回引く。全体を眺めるときは `node scripts/linkedin/find-sen.mjs --list`
- 公開前の記事は URL を送れないので対象外（`--all` を付けない）

優先順位は ①相手の会社や製品の事例が収録されているもの ②相手が解決している課題と同じ課題のもの ③相手の顧客が抱えていそうな隣接課題のもの。上位3本まで比較して1本に決める。

URL はスクリプトが出した `https://vizlabo.com/articles/<slug>` をそのまま使う。存在しない URL を作らない。slug を手で打ち直さない。

近いものがなければ「該当なし」とし、近い課題名と、新しく作る場合のセレクション案を1行出す。この場合、文面は作らない。

## 手順3：文面を作る

- 挨拶（1行。パターン2では受信メッセージへのお礼を一言）
- 相手の領域に触れる一文（褒め言葉で盛らない。プロフィールにある事実だけ）
- 事例マニアの一文紹介：企業の導入事例を課題別に集め、「同じ課題を他社はどう解決したか」を見比べられるメディア
- 「ちょうど〇〇の事例をまとめたセレクションがあります」として、URL を1つ載せる。〇〇は記事の課題を相手の言葉に寄せて言い換える
- 締めは「ご参考までに」「よろしければご覧ください」程度。質問や返信を促す言葉は入れない

## 出力

```
■ 判定：パターン1（こちらから送る）／パターン2（受信への返信）
■ 相手の領域（1〜2行）
■ 候補セレクション（上位3本：タイトル／URL／理由1行）→ 採用した1本
■ 文面
① 短め：150字前後
② 標準：250字前後
```

## 文体

- です・ます調。硬すぎない
- 絵文字・ハッシュタグなし。URL は1つだけ
- 勤務先、会社員であること、副業であることは出さない
- 「弊社」「当社」も使わない（運営者個人として書く）
- 相手の売り込みへの返答（導入する・しない、検討する）は書かない。パターン2でも、お礼のあとは事例マニアの紹介に移る

## 例

入力（パターン1）：
```
山田太郎　株式会社○○ 営業部長
請求書のAI-OCR「△△」を経理部門に提供。年間○万枚の請求書処理を自動化…
```

検索：
```bash
node scripts/linkedin/find-sen.mjs 請求書 経理 "AI-OCR|OCR" --vendor ○○
```

文面（短め）：
```
はじめまして、角田と申します。つながりをありがとうございます。
請求書のAI-OCRを経理部門向けに提供されているのですね。
私は「事例マニア」という、企業の導入事例を課題別に集めて「同じ課題を他社はどう解決したか」を見比べられるメディアを運営しています。
ちょうど経理・バックオフィスの業務をAIに任せた事例をまとめたセレクションがあります。
https://vizlabo.com/articles/499bc233-3d57-42b8-b403-fa6719d0b605
ご参考までに。
```
