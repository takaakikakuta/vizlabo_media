# 事例セレクションの点検

`/sen-check <記事番号|ファイル名>`。作業ディレクトリは `vizlabo_media`。書き方の基準は `content/articles/WRITING-sen.md`。

点検は2段で行う。1段目のスクリプトは数字と決まりごとを照合し、2段目の読み手レビューは文の意味を見る。スクリプトは意味の取れない文を拾えないし、読み手レビューは数字の照合を取りこぼす。どちらか片方では足りない。

## 1. スクリプトで照合する

```
node scripts/verify/sen-check.mjs <番号>
```

- **NG** は直す。body の長さ（80〜130字）、事例データでは見込み・予定の数字なのに断りがない、結びの「〜1本。」、「選んだ・入れた・置いた」4回以上、ダッシュ3回以上。
- **要確認** は1件ずつ事例データと見比べて判断する。
  - 「事例データに見つからない」：計算した数字（差額・合計）なら、元の数字から正しく出せるかを確かめる。別の指標の数字を書いていたら直す。
  - 「事例データでは『6割』」のような言い換え：数字が合っていても、**指標**（紙の量か費用か、件数か時間か）が同じかを確かめる。違えば見出しを事例データの指標に合わせる。
  - 「results が空の事例だが、見出しに数字がある」：数字の出どころが事例データの文の中にあるかを確かめる。
- 判断の結果、直さないと決めた要確認は、ユーザーへの報告に理由を1行で書く。

## 2. 読み手レビュー（別のエージェントに読ませる）

書いた本人は、言いたかったことを知っているので、意味の取れない文を頭の中で補って読めてしまう。だから記事を書いた文脈を持たないエージェントに読ませる。

1. 材料を書き出す：`node scripts/verify/sen-check.mjs <番号> --dump > <スクラッチパッド>/sen-<番号>-review.md`
2. Agent ツールで `general-purpose` を1つ起動し、下のプロンプトを渡す。**書いた意図や、どこが怪しいと思っているかは伝えない**（伝えると、その確認だけで終わる）。

```
事例セレクションの記事を、初めて読む読者として点検してください。材料は <ファイルのパス> にあります。
記事の各項目（見出し・body）の下に、その事例の元データ（課題・施策・成果）を並べてあります。
lead と outro もあります。ファイルを読む以外の作業はせず、書き換えもしないでください。

見るのは次の3つです。

A. 意味が通るか
   body・lead・outro の各文を「誰が・何を・どうした（どうである）」の形に言い換えてください。
   言い換えられない文、主語や指している相手が分からない文、比喩のままで何をしたのか分からない文
   （例：「理由を〜で埋めた」「〜に近い」「〜が中身だ」）を挙げてください。

B. 事例データにない事実を書いていないか
   見出しと body の事実・数字・因果が、その項目の事例データで裏付けられるかを確かめてください。
   データにない程度の言葉（「大半」「すべて」「唯一の原因」）や、データと違う指標
   （データは紙の枚数なのに記事は費用、など）、見込みの数字を実績として書いていないかも見てください。

C. 比較が正しいか
   「01と並ぶ」「05がメールだったのに対し」「10本でここだけ」「ほかの9本と違い」のような、
   ほかの項目と比べる文が、全項目の事例データに照らして正しいかを確かめてください。

報告は項目番号ごとに、問題のある文をそのまま引用し、A/B/C のどれか、何が分からないか（何と食い違うか）を
1〜2行で書いてください。直した文の案は不要です。問題がない項目は「問題なし」とだけ書いてください。
指摘は確信のあるものだけにし、好みの問題（言い回しの好き嫌い）は含めないでください。
```

3. 返ってきた指摘を、事例データと見比べて採るかどうか決める。読み手の誤読による指摘もあるので、全部は採らない。採った指摘は、記事の基準（WRITING-sen.md 2節・7節）に沿って直す。直すときは、元の文が言おうとしていたことを残し、主語と動作が文単体で分かる形にする。

## 3. 仕上げ

1. 直した後にもう一度 `node scripts/verify/sen-check.mjs <番号>` を通し、NG が0件になっていることを確かめる。
2. WRITING-sen.md 7節のとおり、文章チェック（yomiyasu）も通す。body を1項目1段落のテキストに書き出して `python3 .claude/skills/yomiyasu/scripts/yomiyasu_lint.py <ファイル>`。
3. リンクのみに耐えるかは `node scripts/link-only/check.mjs --as-if <番号>`。
4. ユーザーには、直した項目と理由を表で報告する（元の分かりにくい箇所 → どう直したか）。事実の誤り（数字・指標・見込み）は表と分けて書く。直さなかった要確認・指摘は理由を添える。
5. コミットする。メッセージは「事例セレクションNN: …」。
