テレビ連動ポスト生成（事例マニア）

ビジネス番組で特集される企業を調べ、事例DBから関連する事例を探して、X用の本体ポストとリプを作る。番組情報の取得、事例探し、ポスト作成までを1回で行う。

【入力】
$ARGUMENTS に番組名と放送日を渡す（例: カンブリア宮殿 2026-11-19）。
放送日を省略したときは、その番組の次回放送を対象にする。

【対象番組と情報源】
- 知られざるガリバー｜テレ東 土曜18:00｜テレ東の番組表の詳細ページ（broad_tvtokyo/program/detail/…）｜放送前に社名が出る｜UTM名: gulliver
- カンブリア宮殿｜テレ東 木曜23:06｜https://www.tv-tokyo.co.jp/cambria/ の次回予告｜放送前に社名が出る｜UTM名: cambria
- ガイアの夜明け｜テレ東 金曜22:00｜https://www.tv-tokyo.co.jp/gaia/ の次回予告（放送後は backnumber4/preview_YYYYMMDD.html）｜直前までタイトルのみのことが多い｜UTM名: gaia
- がっちりマンデー!!｜TBS 日曜7:30｜TBSの番組公式サイト｜回によって異なる｜UTM名: gacchiri
放送時間は変わることがあるので、毎回公式ページで確認する。
公式ページで社名が分からないときは、WebSearchで番組表・公式Xの告知を探す。

【手順1】回のタイプと「番組で描かれる課題」を確定する
公式ページから、放送日、回タイトル、紹介文、特集企業（主役）、関連して登場する企業を取り出し、回のタイプを決める。
- 企業特集型: 特定の1社（または少数の企業）に焦点を当てる回。ガリバー、カンブリアはほぼこれ。
- テーマ型: 社会課題や業界のテーマに焦点を当て、複数の企業が登場する回。ガイアに多い。特集企業が分からない回もこれとして扱う。
次に、紹介文から「番組で描かれる課題」を1〜2個、短いキーワードで取り出す。
- 企業特集型: その企業の挑戦や強みを課題に言い換える（例: 「1000種類以上のエンジンを作り分ける」→「多品種少量生産」、「経営再建計画でコスト改革」→「コスト削減・経営再建」、「医療・化粧品・半導体へ多角化」→「事業転換・新規事業」）。
- テーマ型: 回のテーマをそのまま課題にする（例: 「働く！じーちゃん ばーちゃん」→「シニア人材の活用」）。
- 紹介文に書かれていない課題を推測で足さない。

【手順2】事例DBから事例を探す（優先順位どおりに探し、見つかった段階で止める）
事例DBの場所と列名（このリポジトリの実物。型定義は lib/types.ts の CaseStudy）:
- 場所と形式: data/cases.json。1事例＝1オブジェクトのJSON配列（約1.1万件・1行の巨大ファイルなので Read せず、node -e で絞り込んで読む）。
- ベンダー企業: vendor。会社名ではなく掲載元サイトのドメイン（例: "3ac.jp"）が入っている。会社名の列はないので、特集企業の公式サイトのドメインを調べて vendor と照合し、あわせて product（製品・サービス名）、sourceUrl（元の事例ページURL）、title、summary も社名・製品名で部分一致検索する。
  - data/intro_sources.json の sources[].domain にある vendor は紹介元（自治体・業界団体・メディアなど）で提供元ではない。Aのベンダーとして扱わず、リプの「ベンダー名」にも書かない。
- 導入企業: customer.name（非公開の事例では空。空の事例は社名を出せないので、Bには使えず、Cでも後回しにする）。
- 業種: customer.industry（slug。manufacturing=製造業 / it=IT・ソフトウェア / construction=建設・不動産 / logistics=物流・運輸 / medical=医療・介護 / finance=金融・保険 / retail=小売・EC / food=飲食・食品 / education=教育 / hr-service=人材サービス / public=自治体・公共 / energy=エネルギー・環境 / other-industry=その他。定義は lib/taxonomy.ts の INDUSTRIES）。other-industry の細分は data/case_facets.json の <事例id>.industry。
- 課題: challenges（slugの配列。cost=コスト削減 / labor=人手不足・省人化 / efficiency=業務効率・工数削減 / quality=品質・不良 / leadtime=納期・リードタイム / standardize=属人化・標準化 / data=データ活用・可視化 / sales=売上・リード獲得 / cs=顧客対応・CS / hr=採用・育成 / security=セキュリティ・コンプラ / sustainability=環境・サステナ。定義は lib/taxonomy.ts の CHALLENGES）。12分類は粗いので、手順1のキーワードは tags（困りごとタグ・自由記述の配列）、challengeDetail（課題の具体）、title、summary の部分一致でも探す。
- 掲載NGフラグ: 次のどれかに当たる事例は使わない（サイトと同じ除外。lib/cases.ts）。
  - hidden: true（削除依頼を受けた事例）
  - linkOnly: true（取り下げ依頼で要約をやめた事例。事例ページがない）
  - vendor が data/blocked_vendors.json の vendors[].domain にある（掲載禁止ベンダー）
- ポストに使う列: title（事例タイトル）、background・challengeDetail（Before）、actions（施策）、results[]（metric・value。定量成果）、resultsQualitative（定性成果）、hasNumbers（数字あり。true を優先）、product（製品名）。
- 事例ページURL: https://vizlabo.com/cases/<id>
- 検索リンクの q は title・summary・product・customer.name・vendor・業種名・課題名・tags を対象に部分一致する（空白区切りはAND）。日本語はURLエンコードし、候補の事例が実際に当たる語を選ぶ。
社名は表記ゆれを考えて部分一致で照合する（例: 「串カツ田中」と「ユニシアホールディングス」、「(株)」の有無、英字とカナ）。
- A: 特集企業がベンダーとして出している導入事例（ベンダー企業 = 特集企業）。切り口は「番組では映らない、特集企業の顧客側の話」
- B: 特集企業に導入された事例（導入企業 = 特集企業）。切り口は「特集企業の裏側を支えていた仕組み」
- C: 番組で描かれる課題と同じ課題を解いた事例（課題 = 手順1のキーワード）。切り口は「同じ課題を、別の会社はこう解いた」
ルール:
- テーマ型の回はA・Bを飛ばしてCから探す（登場企業が分かっている場合は、A・Bも先に確認してよい）。
- AとBの両方があるときはAを本体に使い、Bをリプに足してよい。
- Cは、特集企業と同じ業種の事例を先に探し、なければ業種を問わず探す。最大3件。条件の違う会社（規模・業種・解き方）を混ぜる。
- 関連企業でAやBに当たるものがあれば、主役企業がCのときに限り、リプで1件だけ紹介してよい。
- どの優先度でも見つからなければ、ポストは作らずにその旨をメモに残す。

【手順3】ポストを作る
本体ポスト（140字以内）
- 1行目: 番組名と放送日時（例: 「今夜23時06分のカンブリア宮殿は〇〇」）
- 続けて、手順2の切り口に沿って事例の状況（Before）を書く。
- 最後は「そしたら、」「結果、」などのつなぎ言葉だけで終え、結果はリプの1行目で受ける。本体では結果を言い切らない。
- ハッシュタグ（例: #カンブリア宮殿）は、つなぎ言葉の前の行に入れる。つなぎ言葉は本文の最後に置く。
- 本体にはURLを入れない。問いかけや「詳しくはリプで」などの誘導文は入れない。
リプ
- 1行目: 本体のつなぎ言葉を受ける結果（数字があれば数字）
- 2行目: 導入企業名×ベンダー名・製品名
- 事例ページURL（複数事例のときは、絵文字＋1行要約＋URLを並べる）
- 最後に、事例マニアの検索リンク（https://vizlabo.com/cases?q=<企業名または課題キーワード>）
テーマ型の本体ポスト
- 1行目: 番組名と放送日時、テーマ
- つなぎの一文のあと、絵文字付きで事例3件を1行ずつ（導入企業名と結果）
- この形ではつなぎ言葉で切らなくてよい。リプには各事例のURLと検索リンクを置く。
UTM
- vizlabo.com へのリンクには、すべて次のパラメータを付ける:
  utm_source=x&utm_medium=social&utm_campaign=tv_<UTM名>&utm_content=<放送日YYYYMMDD>
- 例: https://vizlabo.com/cases/xxx?utm_source=x&utm_medium=social&utm_campaign=tv_cambria&utm_content=20261119
- 検索リンクは ?q= のあとに & でつなぐ。

【手順4】守ること
- 番組ロゴ・放送画面・番組の画像は使わない。番組の内容は公式ページの紹介文の範囲で、一言の要約にとどめる。
- 番組がまだ放送していない内容（結論・結果）を推測して書かない。
- 番組の公式アカウントと誤解される書き方をしない。
- 事例の数字や事実は、DBの記載と元の事例ページにあるものだけを使う。
- 掲載NGフラグが立っている企業の事例は使わない。

【出力】
tv-posts/YYYY-MM-DD_番組名.md に次の項目で保存する。
- 見出し: {番組名} {放送日} {放送時間}
- 回タイトル
- 回のタイプ（企業特集型 / テーマ型）
- 特集企業（主役／関連）
- 番組で描かれる課題
- 情報源URL
- 採用した優先度（A / B / C）
- 使った事例（事例タイトル｜事例ページURL を件数分）
- 予約投稿の目安: 放送開始の5分前
- 本体ポスト
- リプ
- メモ（表記ゆれで照合したもの、見送った候補とその理由など）
最後に、作ったファイルのパス、回のタイプ、どの優先度で事例が見つかったかを1行で報告する。
