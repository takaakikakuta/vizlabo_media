# 「業界を越える事例」記事（ekkyou型）の書き方

一見遠い業種の2事例を並べ、**共通する仕事の構造**を読み、**異業種から借りられる工夫**と**そのまま持ち込めない条件**を渡すフォーマット。

企画の起点は、**「業種の言葉を外したら、同じ骨組みが現れた事例はどれとどれか」**。

wakaremichi型が「同じ悩み・違う解き方」の**違い**から分岐を読むのに対し、ekkyou型は「違う業界・同じ構造」の**共通点**から応用先を広げる。同じ業種の事例だけを探す読者に、自分では探さなかった事例を届けるのが役割。事例数に加えて業種の広がりがあるこのサイトだからできる企画である。

## 0. この記事の性質と限界

- 「同じ構造」は編集部の抽象化である。**「どちらも情報共有が大事」のような大きな括りで終わらせない。** 誰から誰へ、何を、いつ渡す必要があるのか——構造の対応は具体の粒度まで下ろす。
- 2事例の一致から一般論は導けない。「この構造はどの業界にもある」とは書かない。
- 「借りられる工夫」は、事例本文で確認できる取り組みを別業種の状況に置いてみる読みであり、効果の保証ではない（テンプレートが断り書きを付けるが、本文でも読みの範囲を守る）。

## 1. ペアを選ぶ

- **業種が実際に遠いこと。** 隣接業種（建設と不動産など）では「越境」の驚きが出ない。
- **課題文・施策に、構造を対応させられる具体的な記述があること。** 抽象的な課題文同士は、何とでも「共通」してしまうので選ばない。
- **両方に、相手の業種へ持ち込める具体的な工夫（進め方・体制・運用）が書かれていること。** 片方からしか借りられないペアは弱い。
- 共有タグは手がかりになるが、タグの一致＝同じ構造ではない。**必ず課題文で骨組みを確認する。**

執筆前に、構造を1文で書く。

> 例：仕事をする人と情報の置き場所が離れていて、情報は一カ所に人手で書き込まれ、離れた人は移動・電話・メールで取りに行くしかない。

この1文が**業種の言葉を使わずに**書けないペアは捨てる。

## 2. 執筆前に、事実と読みを整理する

| 区分 | 内容 |
| --- | --- |
| 本文で確認できる事実 | 両社の課題・施策・成果、導入の進め方 |
| 編集部の読み | 構造の対応づけ、借りられる工夫の置き換え |
| 分からないこと | 成果の内訳（構造以外の要因）、他業種で同じ効果が出るか |

- 成果の数字は「他の施策や状況を含んだ数字」であることを、構造の効果と混同させない書き方で扱う。
- 2社が導入した製品・業務の中身が別物であることを隠さない。共通しているのは**手の入れ方の骨組み**である。

## 3. 構成

扉（業種×業種・タイトル・リード）
→ サムネイル（任意。未設定なら事例画像に自動フォールバック）
→ 目次
→ 一 一見遠い、2つの現場（sceneNote＋課題文の自動引用）
→ 二 共通する仕事の構造（structureIntro＋対応表）
→ 三 異業種から借りられる工夫（borrows）
→ 四 そのまま持ち込めない条件（limits）
→ 結び（closing）＋ 両事例への導線
→ ポリシー表記

### 対応表（structure）の作法

- 行のラベルは「離れた場所にいる人」「情報の置き場所」のような**構造の言葉**にする。業種の言葉はセルの中（a / b）に置く。
- 「打った手」の行を置く場合も、製品名でなく変えた工程で書く。
- 比較上の重要な違い（製品・業務の中身が別物であること、成果の数字の限界）は `structureNote` で必ず断る。

## 4. 執筆の作法

1. **構造は具体まで下ろす。** 「誰から誰へ・何を・いつ」まで対応させられない共通点は、共通点ではなく類似の印象である。
2. **借りる方向を明示する。** 「Aから借りてBへ」「BからAへ」の両方向が成立するのが理想形。工夫の記述は必ず事例本文と照合する。
3. **持ち込めない条件を必ず書く。** 巻き込む相手の違い、情報の出どころ、規制や商習慣など、構造が同じでも移植できない理由を挙げる。最後の1項は「この2事例から一般化できない」ことの明示に使ってよい。
4. **結びは読者の探し方に返す。** 「自社の困りごとを業種の言葉を外して書いてみる」のように、異業種の事例を探すための持ち帰りで締める。特定の製品や業界を推さない。

## 5. 公開前の編集チェック

- 構造の1文が、業種の言葉なしで書けているか。
- 対応表の各セルが、事例本文の記述と一致するか。
- 「どちらも◯◯が大事」で終わる大きな括りになっていないか。
- 製品・業務が別物であることを断ったか。成果の数字に限界を付けたか。
- 借りられる工夫は両方向あるか。効果の保証をしていないか。
- 持ち込めない条件が具体的か。2事例からの一般化を避けたか。
