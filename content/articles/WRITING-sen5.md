# 「選」記事（sen型・事例5選）の書き方

**ひとつの課題を一本の線に切り、線上の別の位置に立つ5社を並べる**記事。読者は自社がいまどの位置で止まっているかを見つけて、その1社から読む。
テンプレートは10選・3選と同じ `format: "sen"`（`items[]` を5件にすれば目次・カルテ・成果チップは01〜05で自動的に組まれる）。5選では `compare`（比べる表）を使い、`fit` で読者の位置を返す。

5選になるテーマの定義は、**10選のテーマを1段ズームインしても、まだ5つの位置と4本の数字が残るテーマ**。
10選のタイトルは「テーマ」で幅を見せ、3選のタイトルは「主張」でひとつ持ち帰らせる。5選は「地図」で、課題の中のどこで止まっているかを読者に当てさせる。10選の書き方は [WRITING-sen.md](WRITING-sen.md)、3選は [WRITING-sen3.md](WRITING-sen3.md)。

## 0. この記事の性質と限界

- **順位を付けない。** 5本でも並列の「選」であり、ベスト5ではない。並び順は線の順（工程の上流から、地震が起きてから時間が経つ順、データを置いた距離が近い順）。
- **規模順に並べない。** 規模は位置を説明しないし、読者が自分の規模の1社しか読まなくなる。規模は `compare` の行に置く。
- 数字は各事例の `results` に記録された公開情報のみ。**タイトルに使う数字は必ず記事内の5本のもの**。数字のない事例は5本中1本まで（線引きは [WRITING-sen.md](WRITING-sen.md) の6節）。
- 位置と手の対応は「この5本の範囲での観察」であり、同じ位置で止まっていれば同じ手が正しいことを示さない。`compare.note` と `outro` に書く。
- `fit` は手がかりであって診断ではない。「〜なら01に近い」と書き、断定しない。

## 1. 企画の判定：5選か、3選か、攻略地図か

候補の事例を読み、各社の施策を表にしてから決める。

| 5社の施策を並べると | 型 |
|---|---|
| 課題の中の**別の位置**に1社ずつ座る（工程・時間・距離が違う） | **5選**（この記事） |
| **同じ手**を、深さ違いでやっている | 3選（主張型。[WRITING-sen3.md](WRITING-sen3.md)） |
| **2〜3本のルート**に複数社ずつ束なる | 課題の攻略地図型（[WRITING-chizu.md](WRITING-chizu.md)） |

5選と攻略地図型の線引きは、位置ごとに1社で成果の数字が出せるかどうか。ルートに複数社が束なり、1社では代表できないなら攻略地図型。

件数の目安は、**素材級（課題文80字以上かつ、数値成果があるか施策80字以上）が10件前後、うち数字ありが4件以上**。数字なしは1本までなので、数字が3本以下なら5選は組めない。困りごとタグは細かく割れていて集計に向かないので、課題文のキーワードで切る。

```bash
python3 -c "
import json,re;cs=json.load(open('data/cases.json'))
txt=lambda c:' '.join(str(c.get(k) or '') for k in ('title','summary','challenges','challengeDetail','actions'))
ok=lambda c:len(c.get('challengeDetail') or c.get('challenges') or '')>=80 and (c.get('hasNumbers') or len(c.get('actions') or '')>=80)
for name,pat in [('バックアップ・DR',r'バックアップ|ディザスタリカバリ'),('停電・電源',r'停電|非常用電源|自家発電|蓄電'),('データセンター移設',r'データセンター.*(移設|移行)'),('安否確認',r'安否'),('水害',r'水害|浸水|豪雨|洪水')]:
  m=[c for c in cs if re.search(pat,txt(c))];s=[c for c in m if ok(c)]
  print(name,'該当',len(m),'素材級',len(s),'うち数字あり',sum(1 for c in s if c.get('hasNumbers')))"
```

災害（No.43）を1段ズームインした例（2026-10-24時点）：

| 課題 | 素材級 | うち数字あり | 判定 |
|---|---|---|---|
| バックアップ・DR | 54 | 20 | 5選も10選も組める |
| 停電・電源 | 23 | 13 | 5選に向く |
| データセンター移設 | 18 | 9 | 5選に向く |
| 安否確認 | 10 | 3 | 数字が足りない。主張が立てば3選 |
| 水害 | 8 | 0 | 選では組めない。舞台裏型か攻略地図型 |

## 2. 線の引き方

1. **課題の中で、止まる場所が複数に分かれているか**を課題文で確かめる。「災害に備えたい」は建物・人・電気・システム・データで止まり、「食品工場の人手不足」は充填・包装・検査・搬送・出荷判定で止まる。止まる場所が1つしかない課題は3選か攻略地図型。
2. 止まる場所を**一本の順序**に並べる。使える順序は3つ。
   - 工程順：設計→図面→成形→プレス→点検（No.39 金型）、充填→包装→検査→搬送→出荷判定（No.42 食品工場）、売り物→客集め→営業→基盤→組織（No.41 新規事業）
   - 時間順：地震が起きてから止まるもの、建物→人→電気→システム→データ（No.43 災害）。ズームインすると「停電から何分で何が止まるか」、照明→生産設備→サーバー→通信→復電後の復旧
   - 距離順：データをどこまで遠くに置いたか、同じ建物の別サーバー→別拠点→クラウド→多重化→復旧を委託
3. 5という数は、線を切ったときに自然に出る数（4〜6）に合わせる。位置が4つしかなければ4選でよい。位置を無理に増やして5にしない。
4. 線の名前を一文で書く（「5社が手を打った場所を、地震が起きてから時間が経つ順に並べた」）。この一文が `lead` の末尾と `compare.intro` に入る。

## 3. 5社の選び方

1. 位置ごとに1社。同じ位置に2社入れない。
2. 数字のある事例を4本以上。数字のない1本は、変化が出来事（移設の翌年に本社が停電したが、データセンターは動いていた）で書けるものだけ。
3. 提供元（ベンダー）は5本とも別にする。
4. 線の順に並べたとき、`headline` だけ読んで位置が分かる5本を選ぶ。
5. 落とした事例と理由をメモに残す。

## 4. 構成とフィールド

扉（title・lead）→ サムネイル → この話の背景（trivia・任意）→ 目次 → 01〜05 → **5社を比べる（compare）** → まとめ（outroTitle・outro）→ あわせて読む → 掲載サービス（自動）

| フィールド | 5選での書き方 |
|---|---|
| `title` | 2行。1行目は記事内の1社の数字か出来事（本社が停電した日、サーバーは動いていた。／1日200食の手詰めが、5,000食になった。）、または線そのものを問いにする（新規事業は、売り物、客集め、営業、基盤、組織のどこで止まっているか。）。2行目はテーマ＋「5社の事例5選」のように本数を明示。3選のような主張の言い切りにはしない（5社に共通する主張がないのが5選） |
| `lead` | 課題は会社全体に一度に打てる手ではなく、止まる場所が一つずつ違うことから入る。5社の位置を1社1句で並べる（Aは建屋の補強に15年かかると言われ、Bは連絡のつかない社員が出て……）。線の名前を言い、**「自社でいま止まっているのはどこか」の問いで締める**（3選では禁じている締め方だが、5選では地図の入口になる） |
| `trivia` | 任意。線の背景にある制度・技術（衛生マニュアルの2時間ルール、RPO/RTO の意味）があるときだけ。書き方は [WRITING-sen3.md](WRITING-sen3.md) 4節 |
| `items[]` | 5件。並び順は線の順。`headline` は見出し規範に従い、その社の位置と数字（か出来事）が見出しだけで分かるようにする。`body` は〈その社が止まっていた場所と条件 → 取った手 → 何がどれだけ変わったか → 読者が自社に当てはめられる一言〉。会社名・業種・規模・成果チップ・リンクはテンプレートが出すので重複させない |
| `compare` | **使う。** `title` は「5社を比べる」。`intro` に線の名前。`rows` は位置の行（守ったもの／渡した工程／詰まった場所）を先頭に、規模・動けなかった条件・取った手・成果の順。`values` は items と同順。`fit` に「〜なら01に近い。〜なら02。」と5つ並べ、断定しない。`note` に、位置と手の対応がこの5本の範囲の観察であることと、数字のない項目・見込み値がどれかを書く |
| `outroTitle` / `outro` | 下記5節 |
| `relatedSlugs` | ズームインする前の10選があれば必ず入れる（10選は幅、5選は地図、3選は気づき） |

## 5. まとめ（outro）

4つの内容を順に書く。`\n\n` で段落を分けてよい。

1. **位置はばらばらでも、手に共通していたこと**。課題文と施策で確認できる範囲で言い切る（どの会社も、災害が来なければ無駄になる投資ではなく、平時の業務に効く形で備えている）。
2. **位置を決めていたもの**。この5本の範囲で、なぜその社はその位置で止まったように見えるか。「この5本の範囲では」で書く。
3. **成り立たない条件**。線に乗らない現場、前提になっている投資、数字が公開されていない社。製品推薦にしない。
4. **読者の次の一歩**を1〜2文。「自社で最初に止まるものを一つ書き出す」のように、自分の位置を決める観察で終える。表に当てる案内を書くなら「比べる表」と呼び、「上の表」のような位置に依存する言い方はしない。

`outroTitle` は1の共通点を短く。

## 6. 公開前チェック

- 5社の位置が線上で全部違うか。並びが線の順で、規模順になっていないか。見出しだけ読んで位置が分かるか。
- 線の名前が `lead` 末尾と `compare.intro` にあり、同じ言い方か。
- 各 body の条件・手・数字が事例データ（課題文・施策・成果）と一致するか。動機や判断を補っていないか。
- 数字のない事例は1本までか。`compare.note` と `outro` に書いたか。見込み値に断りがあるか。
- `fit` が5つあり、断定していないか。
- 提供元が5本とも別か。
- タイトルの数字が記事内の事例のものか。
- `.claude/skills/yomiyasu` のリンターを通したか（lead・items・compare の intro/fit/note・outro を全部含めて検査する）。
- 同じズームイン元の10選を `relatedSlugs` に入れたか。

## 7. 公開手順

基本手順は [WRITING-wakaremichi.md](WRITING-wakaremichi.md) と同じ。`format` は `"sen"`、`items` を5件にし、`compare` を足す。サムネイル未設定時は先頭事例の画像に自動フォールバックする。

## 8. 変更の経緯

2026-10-24 まで、5選に専用のガイドはなく、10選の縮小版として書かれていた。既存の4本（No.39 金型、No.41 新規事業、No.42 食品工場、No.43 災害）を並べると、どれも課題を一本の線（工程・時間）に切り、5社が線上の別の位置に立ち、`compare.fit` で読者の位置を返す作りで共通していたので、同日この型を5選の定義にした。同日に3選を「ひとつの気づきを、やり方の違う3社で見せる」に改めたことで、旧3選が担っていた「条件の違う会社を比べて自社の位置を判定する」役割は5選に移った。
