# 「選」記事（sen型・事例10選／3選）の書き方

1つのテーマで掲載事例から10本を選び、**並列の「選」**として成果の数字とともに紹介するフォーマット。検索流入の入口を担う。

本数を3本（5本以下）に絞った**「3選」**も同じ `format: "sen"` で書ける。`items` の本数だけで誌面が自動で切り替わる（専用フラグは無い）。

| | 10選（一覧レイアウト） | 3選（深掘りレイアウト） |
|---|---|---|
| 条件 | `items` が6本以上 | `items` が5本以下 |
| ねらい | 数で見せる。テーマの広がりと数字の並びで読ませる | 1本ずつ読ませる。3社の中身の違いまで書く |
| 番号 | 01〜10 | 一・二・三 |
| 目次 | 見出しの箇条書き | 顔ぶれカード（事例画像＋見出し＋会社）を3列で一望 |
| 各項目 | 見出し＋1行カルテ＋本文2〜3文＋成果2つ | 見出し＋事例画像＋カルテ4項目（企業・業種・規模・導入したもの）＋本文4〜6文＋成果4つ |
| 題字・一覧 | 「10選」チップ（薄い枠） | 「3選」チップ（濃い枠）＋タイトルの頭に「特選」の札（記事・一覧・ページタイトル。文言は `lib/articles.ts` の `SEN_SHORT_LABEL`） |

3選にするのは、**素材が3本しか無いときではなく、3本で読み比べると違いが立つとき**（同じ課題に対して条件や打ち手が違う3社など）。本数合わせで薄い10本を並べるより、濃い3本のほうがいい、という判断で使う。

企画の起点は、**「そのテーマで、素材級の事例が何件あるか」**（数値成果あり×課題文が厚い事例で15件以上が目安。10件ぴったりでは選べない）。

## 0. この記事の性質と限界

- **順位を付けない。** 「10選」は並列であり、ランキング・おすすめ順ではない。順番は読みやすさ（数字の大きさ・物語の流れ）の編集判断。
- **選定基準と範囲を冒頭で明示する**（`criteriaNote`）。母数（当サイト掲載◯件のうち該当◯件）、選定基準、順位でないこと、市場の代表性を示さないこと。
- 数字は各事例の `results` に記録された公開情報のみ。**タイトルに使う数字は必ず記事内の事例のもの**にする（選外事例の数字を看板にしない）。
- 見込み値・範囲の限定（〜業務のみ等）は本文で明示する。

## 1. 選定

- 母集団を機械的に抽出（タグ・キーワード・カテゴリ）してから、**全件の内容を読んで**選ぶ。
- 選定基準の例：数値成果が具体的／業務・業種が重ならない／同一ベンダーに偏らない（目安：同一ベンダー3本まで）。
- 落とした事例の理由をメモに残す（基準の一貫性の確認用）。

## 2. 各項目の書き方

- `headline`：見出し規範に従う（情景か発見の断言。カギ括弧強調・ダッシュ補足・講義口調は使わない）。その事例の数字か固有の状況を入れる。
- `body`：10選は2〜3文。〈状況 → 何を読ませたか → 何がどれだけ減ったか〉＋できれば「この1本が示すこと」を一言。事例データ（課題文・成果）の範囲で書き、盛らない。
- `body`（3選）：4〜6文。誌面が1本ずつ独立するので、〈導入前の状況 → 何を変えたか・何を変えなかったか → 数字 → 他の2本との違い〉まで書く。それでも事例データの範囲は越えない。
- 会社名・業種・規模・成果チップ・事例リンクはテンプレートが自動で出す（bodyで重複させない）。

## 3. 構成とフィールド

扉（title・lead）→ criteriaNote（枠）→ サムネイル → 目次（10本の見出し／3選は顔ぶれカード）
→ 01〜10（headline＋カルテ＋body＋成果チップ＋事例リンク）／3選は一〜三（headline＋事例画像＋カルテ4項目＋body＋成果チップ4つ＋事例リンク）
→ まとめ（outroTitle・outro＝並べて見えた共通項と、読者の次の一歩）
→ あわせて読む（relatedSlugs）→ 掲載サービス＋まとめて問い合わせ（自動）→ ポリシー表記

## 4. 公開前チェック

- criteriaNote に母数・基準・「順位ではない」があるか。
- タイトルの数字が記事内の事例の実数か。「◯選」の数が `items` の本数と合っているか（題字・一覧のチップは本数から自動で出る）。
- 各 body の数字・事実が事例データと一致するか。見込み値に断りがあるか。
- 同一ベンダーへの偏りが基準内か。
- まとめが「共通項の観察＋次の一歩」になっているか（製品推薦になっていないか）。
