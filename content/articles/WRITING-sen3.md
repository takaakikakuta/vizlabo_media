# 「選」記事（sen型・事例3選）の書き方

**ひとつの気づきを、やり方の違う3社で見せる**記事。
テンプレートは10選と同じ `format: "sen"`（`items[]` を3件にすれば目次・カルテ・成果チップは01〜03で自動的に組まれる）。3選では扉の直後に `trivia`（この話の背景）を置き、`compare`（比べる表）は原則使わない。

10選との違いは本数ではなく**タイトルの種類**にある。10選のタイトルは「テーマ」（脱炭素の事例10選）で、幅を見せる。3選のタイトルは「主張」（朝ごはんを、朝に作るのをやめた。）で、読者にひとつ持ち帰ってもらう。
1件の深掘りは note の「この事例がスゴイ」が担う。1件だと「その会社の話」で終わり、10件だとテーマに薄まる。主張が立つ最小の数が3件で、3選はそこを受け持つ。
10選の書き方は [WRITING-sen.md](WRITING-sen.md)。

## 0. この記事の性質と限界

- **順位を付けない。** 3本でも並列の「選」であり、ベスト3ではない。
- **3社の間に対比を置かない。** 対比は「読者が今やっていること」と「3社がやったこと」の間に置く（採用 vs 調理の時刻）。3社の間で手が分かれる記事は「分かれ道」型の仕事で、3選でやると読者が製品を選ぶ人になってしまう。
- 数字は各事例の `results` に記録された公開情報のみ。**タイトルに使う数字は必ず記事内の3本のもの**。数字のない事例は3本中1本まで。成果を「何が起きたか」で書き、まとめの限界の段落にその旨を書く（線引きは [WRITING-sen.md](WRITING-sen.md) の6節）。
- 3本から一般化しすぎない。まとめに「この3本の範囲では」の断りを入れ、主張が成り立たない条件を必ず書く。
- `trivia` は事例の外にある知識（制度・技術・数字の由来）を扱う。**一次資料か公的資料で確認できたことだけ**書き、裏が取れない通説（起源の逸話など）は入れない。

## 1. 主張を先に決める

1. **持ち帰ってほしい気づきを、事例を選ぶ前に一文で書く。** 「早番が採れないのは、朝に調理をしているからだ」「二度打ちで高くついているのは、打つ時間ではなく、ずれを探す時間だ」。
   一文で言えないなら、その題材は3選ではなく5選にする。「QRコードの事例を3つ集める」から始めた記事は全部5選行き。
2. 気づきは**読者の常識とずれている**ものを選ぶ。読者が今やっていること（求人を出す、規定を周知する、入力を速くする）と、3社がやったことの間に差があるか。差がなければ主張ではなく説明になる。
3. 気づきは課題文と施策で確認できるものに限る。事例に書いていない動機や判断を補わない。

## 2. 3社の選び方：同じ気づきを、違うやり方で

1. 主張を支える事例を**6件以上**集める（数え方は [WRITING-sen.md](WRITING-sen.md) 参照）。
2. 全件を読み、各社が**同じ気づきをどこまで、どうやって実行したか**を表にする。3社は同じ手を打っていてよい。違うのは「どこまで」で、その軸をひとつ決める。
   - 例：調理をどこへ動かしたか（同じ厨房で時刻だけ → 2つの厨房を1つにして → 調理を外に出す）
   - 例：二度打ちの何を機械に渡したか（打つ手 → システムのつなぎ目 → 照合という判断）
   - 例：往復をどこまで機械に渡したか（人のまま置き場所を変える → 入力中に案内を出す → 判定を機械にする）
3. **軸に沿って3段階になる3社**を選ぶ。規模順はやめる。規模は「どこまで」をほとんど説明しないし、読者が自分の規模の1社しか読まなくなる。
4. 提供元（ベンダー）は3本とも別にする。
5. 落とした事例と理由をメモに残す。

## 3. 構成

扉（title・lead）→ サムネイル → **この話の背景（trivia）** → 目次 → 01〜03 → まとめ（outroTitle・outro）→ あわせて読む → 掲載サービス（自動）

| フィールド | 3選での書き方 |
|---|---|
| `title` | 2行。**1行目は主張を、違和感のある言い方で**（朝ごはんを、朝に作るのをやめた。／出張で一番長いのは、移動ではなく、往復だった。）。読者が「え？」と止まる一文にする。2行目は主張の言い換え＋「やり方の違う3社の事例3選」のように本数を明示。1行目は3社すべてに当てはまる文にする（2社にしか当てはまらない事実は使わない） |
| `lead` | 読者が今やっていることから入り、3社は何をしたかを主張として言い切る。続けて3社の「どこまで」を一言ずつ並べ、「渡した順に見る」「動かした距離が短い順に見る」のように並び順の軸を言って終える。「自社はどれに近いか」の問いでは締めない |
| `trivia` | 下記4節 |
| `items[]` | 3件。並び順は「どこまで」の軸に沿う（小→大）。`headline` は見出し規範に従い、その社の「どこまで」が見出しだけで分かるようにする。`body` は1社1場面。冒頭1文でその社が「何をどこまで動かしたか」を言い、次に具体の場面（前日の午後にトレイができあがっている）、数字、その社ならではの結び。3本で同じ型を繰り返さない。会社名・業種・規模・成果チップ・リンクはテンプレートが出すので重複させない |
| `compare` | 原則使わない。本文の繰り返しになる。載せるなら本文に書いていない事実だけ（導入期間・費用感・諦めたもの） |
| `outroTitle` / `outro` | 下記5節 |
| `relatedSlugs` | 同テーマの10選があれば必ず入れる（3選は気づきの入口、10選は幅） |

## 4. この話の背景（trivia）

本文に入る前に、事例の外にある前提を押さえる枠。3選は本文が短いので、ここが記事の厚みになり、動画にしたときの尺にもなる。**600〜900字、3段落**を目安にする。

- 1段落目：**主張の裏にある制度・決まり・数字**。読者が「なぜ今そうなっているか」を知らない前提で書く（早番5時半の正体は衛生マニュアルの2時間ルール／旅費規程が複雑なのは非課税で日当を払うための副産物）。
- 2段落目：**3社が使った技術・手の仕組み**。それがなぜ主張を可能にするか（クックチルは2時間の時計を止める技術／RPA・連携ツール・専用システムはどこで働くかが違う）。
- 3段落目：**3社の違いを、この知識で言い直す**（温め方は3施設で違う／3社はこの3つの道具をちょうど1つずつ使っている）。本文への橋渡しになる。
- 出典は本文に入れない（記事に出典欄はない）。代わりに、確認した資料をコミットメッセージか作業メモに残す。数字には年を付ける（2023年3月時点で2.92倍）。古い数字を使うときは年を明示し、迷ったら落とす。
- 段落は `\n\n` で区切る。

## 5. まとめ（outro）

4段落。`\n\n` で区切る。

1. **3社に共通していたこと**を、課題文と施策で確認できる範囲で言い切る（3施設が減らしたのは人数というより時刻だ）。主張をここでもう一度、別の角度から言う。
2. **「どこまで」を決めたもの**。この3本の範囲で、何が3社の距離の違いを決めていたように見えるか（厨房の数と食数／二度打ちの相手が自社の中か外か）。「〜のようだ」「この3本の範囲では」で書く。
3. **主張が成り立たない条件**。この手が効かない現場、前提になっている投資、数字が公開されていない社。ここは記事ごとに違う内容になる場所で、書き手が本当に考えたかが出る。製品推薦にしない。
4. **読者の次の一歩**を1〜2文。「自社の◯◯を書き出す」のように、明日できる観察で終える。「上の表」など構成に触れる言い方はしない。

`outroTitle` は1段落目の主張を短く（盛り付けは消えていない。午後に動いただけだ）。

## 6. 公開前チェック

- 主張を一文で言えるか。その一文がタイトルの1行目にあるか。1行目は3社すべてに当てはまるか。
- 3社の「どこまで」が3段階になっているか。並びが規模順になっていないか。見出しだけ読んで段階が分かるか。
- 各 body の場面・数字が事例データ（課題文・施策・成果）と一致するか。動機や判断を補っていないか。
- 数字のない事例は1本までか。まとめの限界の段落に書いたか。
- trivia の事実は資料で確認したか。裏の取れない逸話が入っていないか。数字に年が付いているか。
- まとめに「成り立たない条件」の段落があるか。製品推薦になっていないか。
- 提供元が3本とも別か。
- `.claude/skills/yomiyasu` のリンターを通したか（lead・trivia・items・outro を全部含めて検査する。「AではなくB」の指摘は、主張の切り替えを担っていれば残してよい）。

## 7. 公開手順

基本手順は [WRITING-wakaremichi.md](WRITING-wakaremichi.md) と同じ。`format` は `"sen"`、`items` を3件にし、`trivia` を足す。サムネイル未設定時は先頭事例の画像に自動フォールバックする。

## 8. 変更の経緯

2026-10-24 まで、3選は「同じ課題を抱えた、条件（規模）の違う3社を並べ、読者が自社の位置を判定する」記事で、比べる表（compare）を原則入れていた。本文→表→まとめで同じことを3回言う形になり、規模順は手の違いを説明せず、読者を製品を選ぶ人に置いてしまうため、同日「ひとつの気づきを、やり方の違う3社で見せる」に改めた。最初に書き直したのは #28（給食の早番）。
