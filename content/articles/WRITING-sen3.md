# 「選」記事（sen型・事例3選）の書き方

同じ課題を抱えた3社を、**条件（規模・予算・現場の制約）が違う順に並べ**、読者が「自社はこの3社のどこに近いか」を判定できるようにする短い記事。
テンプレートは10選と同じ `format: "sen"` を使う（`items[]` の件数は固定されていないので、3件入れれば目次・カルテ・成果チップは01〜03で自動的に組まれる）。3選だけが使う任意の `compare`（比べる表）を本文の後に置ける。

10選との違いは本数ではなく**役割**にある。10選は1つのテーマで幅（業種・業務のばらつき）を見せる記事。3選は**同じ課題への選択肢の幅と、手が分かれた条件**を見せ、最後に読者が自社の位置を決められる記事。
10選の書き方は [WRITING-sen.md](WRITING-sen.md)。

## 0. この記事の性質と限界

- **順位を付けない。** 3本でも並列の「選」であり、ベスト3ではない。並び順は条件の軸に沿う（小→大、低予算→高予算、制約が強い→弱い）。
- **選定基準と範囲を冒頭で明示する**（`criteriaNote`）。母数（当サイト掲載◯件のうち同じ課題に該当◯件）、条件を分けた軸、順位でないこと、市場の代表性を示さないこと。
- 数字は各事例の `results` に記録された公開情報のみ。**タイトルに使う数字は必ず記事内の3本のもの**にする。
- 3本から一般化しすぎない。比べる表の `note` とまとめに「この3本の範囲では」の断りを入れる。
- 「自社に近い1社」は読者が決める。記事は判定の手がかり（条件の違い）を並べるだけで、「あなたはこれ」と断定しない。

## 1. 選び方：同じ課題に対して、条件が違う3社

1. **課題を1つに固定する。** 困りごとタグ（例：手作業の転記、業務の属人化）か、課題文の言い回しで母集団を切る。課題が揃っていないと「条件の違い」が読めない。
2. **候補を6件以上**確保する（3件ぴったりでは選べない）。数え方の例（数値成果あり・課題文80字以上をタグ別に集計）：

```bash
python3 -c "
import json,collections;cs=json.load(open('data/cases.json'))
cnt=collections.Counter(t for c in cs if c.get('results') and len(c.get('challengeDetail') or '')>=80 for t in c.get('tags',[]))
print(cnt.most_common(30))"
```

3. 候補の**全件を読み**、各社の条件を表にする。見る条件は次の3つを基本に、課題に応じて足す。
   - 規模（従業員数・拠点数・件数など、`customer.size` と課題文から）
   - 予算（製品の価格帯・導入範囲・内製か外注か。公開情報で読めるものだけ）
   - 現場の制約（紙が残る、IT担当がいない、既存システムを捨てられない、現場が屋外、など課題文の記述）
4. **条件が違い、取った手も違う3社**を選ぶ。条件が違っても同じ手を取っていたら対比にならない。手が違っても条件が同じなら「どちらでもよい」になってしまう。
5. 提供元（ベンダー）は3本とも別にする（10選の「同一ベンダー3本まで」より厳しくする）。
6. 落とした事例と理由をメモに残す（基準の一貫性の確認用）。

## 2. 見せるもの（4つ）

| 見せるもの | どこに書くか |
|---|---|
| **選択肢の幅**：同じ課題に、こう違う手がある | `lead` で3つの手を一言ずつ並べる。各 `headline` は手の違いが見出しだけで分かるように書く |
| **手を分けた条件**：なぜその会社はその手になったか | 各 `body` の1文目に条件、2文目に取った手、3文目に成果。`compare.rows` で条件を行にして並べる |
| **自社に近い1社**：読者が自分の位置を見つける | `compare.fit` に「◯◯なら01、△△なら02、□□なら03」の手がかりを書く。断定しない |
| **3社の共通点**：条件が違っても変わらなかったこと | `outro` の前半。「どの会社も◯◯から手を付けた」など、課題文と施策で確認できるものだけ |

## 3. 各項目の書き方

- `headline`：見出し規範に従う（情景か発見の断言。カギ括弧強調・ダッシュ補足・講義口調は使わない）。その事例の数字か固有の状況を入れる。3本を並べたとき**条件か手の違いが見出しだけで分かる**ようにする。
- `body`：3文。〈その会社の条件 → 取った手 → 何がどれだけ減ったか〉。条件は課題文、手は施策、数字は成果の範囲で書き、盛らない。
- 会社名・業種・規模・成果チップ・事例リンクはテンプレートが自動で出す（bodyで重複させない）。
- 結び「〜1本。」は3本中**1件まで**。ダッシュ「——」は1記事に2回まで。本文の「」は固有名詞・製品名・原典からの引用だけ。

## 4. 締め：3社を比べるパート（`compare`）

本文01〜03の後、まとめの前に入る。省略すると章ごと消えるが、**3選では原則入れる**。

```json
"compare": {
  "title": "3社を比べる",
  "intro": "同じ〈手作業の転記〉を抱えた3社を、規模と現場の制約の順に並べた。",
  "rows": [
    { "label": "規模", "values": ["従業員20名・1拠点", "従業員300名・5拠点", "従業員3,000名・全国"] },
    { "label": "予算・範囲", "values": ["月額数万円のSaaSを1部門で", "既存システムに連携して経理全体", "専用システムを全社で"] },
    { "label": "現場の制約", "values": ["IT担当がいない", "紙の請求書が残る", "基幹システムを替えられない"] },
    { "label": "取った手", "values": ["入力をなくす", "読み取りを任せる", "照合を自動にする"] },
    { "label": "成果", "values": ["月40時間削減", "処理時間60%削減", "年間2.4万時間削減"] }
  ],
  "fit": "IT担当が置けず、まず1部門で試したいなら01に近い。紙が届き続ける経理を抱えているなら02。基幹システムを動かせないまま全社で減らしたいなら03。",
  "note": "条件と手の対応はこの3本の範囲での観察で、同じ条件なら同じ手が正しいことを示すものではない。"
}
```

- `rows` の行は**選び方で見た条件と同じ**にする（規模・予算・現場の制約）。それに「取った手」と「成果」を足して5行前後。列は `items` と同じ順で、見出しの会社名はテンプレートが自動で出す。
- `values` は各セル1行で収まる長さ（15〜25字）。長くなるなら本文に戻す。
- `fit` は読者が自社の位置を判定する手がかり。「◯◯なら01に近い」の形で3つ並べる。製品の推薦にしない。
- `note` に「この3本の範囲では」の断りを必ず入れる。

## 5. 構成とフィールド

扉（title・lead）→ criteriaNote（枠）→ サムネイル → 目次（3本の見出し＋「比べる」）
→ 01〜03（headline＋カルテ＋body＋成果チップ＋事例リンク）
→ **3社を比べる（compare）**
→ まとめ（outroTitle・outro）→ あわせて読む（relatedSlugs）→ 掲載サービス＋まとめて問い合わせ（自動）→ ポリシー表記

| フィールド | 3選での書き方 |
|---|---|
| `title` | 2行。1行目は情景か発見、2行目は「条件の違う3社の導入事例」など本数と見せ方を明示 |
| `lead` | 固定した課題と、3社が取った手を一言ずつ並べ、「自社はどれに近いか」の問いで締める |
| `criteriaNote` | 母数・固定した課題・条件を分けた軸・「順位ではない」・「市場の代表性を示さない」 |
| `items[]` | 3件。並び順は条件の軸に沿う |
| `compare` | 上記4節。原則入れる |
| `outroTitle` / `outro` | 前半に3社の共通点、後半に読者の次の一歩（自社の条件を表に当ててから事例を読む、など）。製品推薦にしない |
| `relatedSlugs` | 同テーマの10選があれば必ず入れる（3選は入口、10選は深掘り） |

## 6. 公開前チェック

- criteriaNote に母数・固定した課題・条件の軸・「順位ではない」があるか。
- 3社の課題が本当に同じか（課題文で確認）。条件が違い、手も違うか。
- タイトルの数字が記事内の3本の実数か。
- 各 body の条件・手・数字が事例データ（課題文・施策・成果）と一致するか。見込み値に断りがあるか。
- 提供元が3本とも別か。
- 3本の見出しを並べて、条件か手の違いが読めるか。
- compare の行が選び方の条件と対応しているか。fit が断定になっていないか。note に範囲の断りがあるか。
- まとめの共通点が課題文と施策で確認できるか。製品推薦になっていないか。
- `.claude/skills/yomiyasu` のリンターを通したか（手順は README.md。compare の intro・fit・note も本文に含めて検査する）。
