# 「事例でわかる技術用語」（yougo型）の書き方

「〇〇とは」で検索した人向けに、用語の説明と、その用語で課題を解いた事例を1記事にまとめるコーナー。説明だけのサイトとの差は事例が付いていること。狙いは検索流入。
`format` は `"yougo"`、`series` は `"事例でわかる技術用語"`。連番 `no` は事例セレクションとは別に数える（サムネイルは `public/thumbnail/yougo-<no>.jpg`）。

## 0. 性質と限界

- 用語の説明は一般的な仕組みの範囲にとどめ、数字を書かない。事例の数字・事実は各事例の `results`・`challengeDetail`・`actions` に記録された公開情報だけを使う。
- 記事の目線は作り手ではなく「自社の課題で同じことがないか」を考える読者。製品の優劣は書かない。
- 事例セレクションと事例が重なってもよい。

## 1. 選定

- 候補は `data/cases.json` を用語（製品名・title・summary・actions・tags）で引く。掲載禁止ベンダー（`data/blocked_vendors.json`）・`hidden`・`linkOnly`（要約を削除し出典リンクのみ）の事例は使わない。
- 本数は指定がなければ3。条件の違う事例が5本揃うなら5。
- 条件が違う会社を選ぶ。業界・企業規模・抱えていた課題のうち、どの2社を比べても最低2軸が異なること。5本のときは業界を3つ以上にまたがらせる。同じベンダーの事例は1本まで。
- 選定理由（なぜこの組み合わせか、何が分かれ目か）を先に短く書いてから本文に入る。

## 2. 構成とフィールド

| フィールド | 記事上の場所 |
|---|---|
| `term` / `title` | 用語と見出し。見出しは「{用語}とは｜{N}つの事例でわかる」 |
| `lead` | 2〜3文。検索した人の疑問に最初の3行で答える。社名・規模・成果の数字は書かない |
| `description` | meta description（120字以内）。`app/articles/[slug]` が検索結果向けに使う |
| `thumbLine` | サムネ用の一行要約（表には出さない。SNS・画像制作用） |
| `definition` | 「一 {用語}とは」（300字程度。専門用語を使わず、何を解決するためのものかを中心に） |
| `fit[]` / `unfit[]` | 「二 向いている課題・向かない課題」（各3つ）。`unfit` は根拠になる事例があれば `caseId` を付けると事例ページへのリンクが出る |
| `items[]` | 事例。見出し（導入企業名 × サービス名）・業種・規模・提供元・成果チップ・事例リンク・出典URLは自動。書くのは `genjo`（現状）→ `nayami`（悩み）→ `uchite`（打ち手）→ `kekka`（結果）→ `hitokoto`（読者が自社に当てはめられる一言）。製品名が長いときは `service` で見出しの表記を短くできる |
| `wakareme` | 「三 {N}社の分かれ目」。`intro`（どの条件の違いで打ち手が変わったか）→ `points[]`（軸ごとの読み。3本のとき）か `table`（5本のときの表。`rows[].values` は items と同順）→ `judge`（自社はどれに近いかを決める問い） |
| `relatedTerms[]` | 「四 関連する用語」。用語記事があればそのURL、無ければ困りごとタグ（`/tag/…`）や製品カテゴリ（`/product/…`）のページ |
| `relatedSlugs[]` | 「四」の「あわせて読む」。関連する事例セレクションの slug |

締め（AI事例サジェスト＋メルマガ登録、掲載サービス一覧と一括問い合わせ、ポリシー表記）はテンプレートが出すので書かない。

## 3. 各項目の書き方

- `genjo`〜`kekka` は各1〜3文。事例データ（課題文・施策・成果）の範囲で書き、盛らない。見込み値・範囲の限定は本文で明示する。
- `kekka` に数字を置く（成果チップと重なってよい）。数字のない事例は、変化を出来事で書く。
- `hitokoto` は読者に向けて言い切る。「〜1本。」「〜を示す事例。」のような編集者の説明は書かない。
- 事例セレクションの歯止め（WRITING-sen.md 7節）をそのまま守る。ダッシュは1記事2回まで、本文の「」は固有名詞・製品名・引用だけ。
- 公開前に `.claude/skills/yomiyasu` のリンターを通す。

## 4. リンクのみに耐える書き方

`title`・`lead`・`definition`・`fit`・`unfit`・`wakareme` には社名・規模・成果の数字を書かない（事例が `linkOnly` になっても書き直さずに済む水準）。`wakareme` で個別の事例を指すときは番号（01・02）で指す。
事例が `linkOnly` になったら `items[].linkOnly.body`（企業名・規模・数字を伏せた1〜2文）を書く。確認は `node scripts/link-only/check.mjs --as-if <記事ファイル名>`。

## 5. 公開手順

1. `python -c "import uuid; print(uuid.uuid4())"` で slug を生成し、`content/articles/yougo-<no>-<用語>.json` を置く（`draft: true` で下書き）。
2. `npm run build` が通ることを確認し、`node scripts/inventory/inventory.mjs` で INVENTORY.md を更新する。
3. 公開するときは `draft` を消し、`publishedAt` を公開日にする。記事URLは `/articles/<slug>`。
