# 記念日ページ（/days）の足し方

SNSの記念日ポストを、1日1ページの読みものとして残す仕組み。`/days` が一覧、`/days/MM-DD` が各日のページ。

1. このフォルダに `MM-DD.json` を1つ置く（例: `10-25.json`）。置くだけでページと一覧に載り、サイトマップにも入る。
2. イラストは `public/days/MM-DD.jpg`（または .png / .webp）を置くだけで反映される。幅1400px程度のJPEG推奨（PNG原本は2MB前後になるので、他のサムネイルと同じくJPEGに変換して置く）。
3. 公開前に確認したいときは `"draft": true` を付ける（一覧・ページ・サイトマップの全部から消える）。

## JSONの項目

| 項目 | 内容 |
|---|---|
| `date` | `"MM-DD"`。ファイル名と同じにする |
| `name` | 記念日の名前（例: 世界パスタデー） |
| `emoji` | リプ欄の行頭に付ける絵文字（任意） |
| `title` | 書き出し。配列の要素1つ＝1行（ポストの1〜2文目） |
| `body` | 本文。ポストの続き（1段落） |
| `theme` | 3本の括り（例: 手仕事の食品づくりを機械に任せた事例）。「○○を3つ、リプ欄に。」の○○ |
| `items` | 事例3本。`caseId`（/cases/の後ろのID）と `note`（ポストのリプ欄の一言）。会社名・数字・リンクはテンプレートが出す |
| `more` | 「もっと見る」の導線（任意）。`label` と `href`（例: `/cases?q=食品`） |
| `image` | イラストを明示したいときだけ（通常は不要。自動検出） |

## ページに出るもの

扉（日付・記念日名）→ イラスト → 書き出しと本文 → 事例3本（一言＋事例カード）→ もっと見る → 前の日／次の日 → ポスト用テキスト（本文とリプ欄を組み立てたもの。コピーしてSNSに貼れる）

事例IDが `cases.json` に無い、または非公開（hidden）の場合、その1本は表示から落ちる（ビルドは止まらない）。
